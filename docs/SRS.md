## 1. 개요

### 1.1 목적
이 문서는 브라우저 퍼즐 게임 "치이카와 합치기"의 사용자 요구사항(UR)과 이를 구체화한 소프트웨어 요구사항(SR)을 정의한다. 각 SR 은 상위 UR, 구현 위치, 검증 테스트 케이스와 추적성으로 연결된다.

### 1.2 범위
떨어뜨린 캐릭터가 물리 법칙에 따라 쌓이고, 같은 캐릭터끼리 닿으면 다음 단계로 합쳐지는 단일 HTML 게임 전체(입력, 물리, 합체 규칙, 점수, 게임 오버, 화면 표시, 배포 형태)를 대상으로 한다.

### 1.3 용어

| 용어 | 정의 |
|---|---|
| 캐릭터(face) | 컨테이너에 떨어뜨리는 원형 물리 객체. 0~9 의 단계(tier)를 가진다 |
| 단계(tier) | 캐릭터 진화 순서. 0 = 치이카와 … 9 = 세이렌 |
| 컨테이너 | 캐릭터가 쌓이는 상단이 열린 상자 (좌우 벽 + 바닥) |
| 위험선 | 컨테이너 상단 근처의 점선. 캐릭터가 이 선 위로 넘쳐 머물면 게임 오버 |
| 조준 X (aimX) | 다음 캐릭터를 떨어뜨릴 가로 위치 |
| 논리 좌표 | 화면 크기와 무관한 게임 내부 좌표계 (440 × 720) |
| DPR | devicePixelRatio. 고해상도 화면의 물리 픽셀 배율 |

### 1.4 요구사항 표기
- **UR-nnn**: 사용자 관점 요구사항 / **SR-nnn**: 시험 가능한 소프트웨어 요구사항
- 작성 규칙은 `.claude/skills/spec-writing/SKILL.md` 를 따른다.

## 2. 시스템 개요

### 2.1 구성

| 구성 요소 | 설명 |
|---|---|
| 물리 엔진 | matter-js 0.19.0 (MIT), HTML 에 인라인 내장 |
| 캐릭터 이미지 | 10종 PNG, data URI 로 내장 (`IMGS`) |
| 렌더링 | HTML Canvas 2D, `requestAnimationFrame` 루프 (`frame()`) |
| 저장 | 브라우저 `localStorage` (최고 기록) |
| 외부 의존 | Google Fonts "Jua" (선택 — 없으면 시스템 폰트) |

### 2.2 화면 배치 (논리 좌표)

```
 y=0   ┌──────────────────────────────────┐
       │ 점수 / 최고          다음 (미리보기) │  HUD
 y=82  │            ( 조준 캐릭터 )          │  DROP_Y
 y=130 ├─┬──────────────────────────────┬─┤  TOP (컨테이너 상단)
 y=148 │ │- - - - - - 위험선 - - - - - - │ │  DANGER_Y
       │ │                              │ │
       │ │          컨테이너             │ │
 y=650 │ └──────────────────────────────┘ │  BOX_B (바닥)
 y=686 │  ① › ② › ③ … › ⑩  (진화 단계)    │
 y=720 └──────────────────────────────────┘
       x=0  BOX_L=14            BOX_R=426  x=440
```

### 2.3 주요 상수

| 상수 | 값 | 의미 |
|---|---|---|
| `W`, `H` | 440, 720 | 논리 해상도 |
| `RADII` | 16, 22, 29, 36, 44, 53, 63, 74, 87, 104 | 단계별 반지름(px) |
| `DROP_Y` | 82 | 드롭 시작 높이 |
| `DANGER_Y` | 148 | 위험선 높이 |
| 중력 | 1.6 | `engine.gravity.y` |
| 드롭 쿨다운 | 550 ms | |
| 게임 오버 유예 | 2.2 s | |

## 3. 사용자 요구사항 (UR)

| ID | 사용자 요구사항 | 우선순위 |
|---|---|---|
| UR-001 | 플레이어는 마우스·터치·키보드로 캐릭터를 원하는 가로 위치에 떨어뜨릴 수 있어야 한다. | 필수 |
| UR-002 | 같은 캐릭터 두 개가 맞닿으면 다음 단계 캐릭터로 합쳐져야 한다. | 필수 |
| UR-003 | 플레이어는 점수와 최고 기록을 확인할 수 있어야 하며, 최고 기록은 다시 접속해도 유지되어야 한다. | 필수 |
| UR-004 | 플레이어는 다음에 나올 캐릭터와 전체 진화 순서를 미리 알 수 있어야 한다. | 권장 |
| UR-005 | 캐릭터가 컨테이너 위로 넘치면 게임이 끝나야 하고, 바로 다시 시작할 수 있어야 한다. | 필수 |
| UR-006 | 휴대폰과 PC 등 다양한 화면에서 끊김 없이 플레이할 수 있어야 한다. | 필수 |
| UR-007 | 설치나 서버 없이 파일 하나로, 인터넷 연결이 없어도 실행할 수 있어야 한다. | 필수 |
| UR-008 | 합체, 보너스, 위험 상황을 화면에서 즉시 알아볼 수 있어야 한다. | 권장 |

## 4. 소프트웨어 요구사항 (SR)

구현 위치의 줄 번호는 [추적성 매트릭스](traceability-matrix.md)에서 소스 기준으로 자동 계산된다.

### 4.1 캐릭터 정의

| ID | 소프트웨어 요구사항 | 상위 UR | 구현 위치 |
|---|---|---|---|
| SR-001 | 캐릭터는 0(치이카와)~9(세이렌)의 10단계로 정의하고, 반지름은 순서대로 16, 22, 29, 36, 44, 53, 63, 74, 87, 104px 로 단계가 오를수록 커야 한다. 단계마다 이미지 1종과 표시 보정값 1쌍을 가진다. | UR-002, UR-004 | `RADII`, `IMGS`, `META` |
| SR-002 | 떨어뜨릴 캐릭터는 0~4단계 중 균등한 확률로 무작위 선택한다. | UR-001 | `randTier()` |

### 4.2 조작

| ID | 소프트웨어 요구사항 | 상위 UR | 구현 위치 |
|---|---|---|---|
| SR-003 | 포인터(마우스·터치)를 움직이거나 누르면 조준 X 를 포인터 위치(논리 좌표 = 화면 좌표 ÷ 배율)로 갱신하고, 포인터를 떼면 그 위치에 드롭한다. 누르기만 해서는 드롭하지 않는다. | UR-001 | `pointerX()`, `pointerup` |
| SR-004 | ← / → 키는 조준 X 를 12px 씩 이동하고, Space / ↓ 키는 드롭하며 해당 키의 브라우저 기본 동작(스크롤)을 막는다. | UR-001 | `keydown` |
| SR-005 | 조준 및 드롭 X 좌표는 현재 캐릭터가 벽 안쪽에 들어가는 범위 [BOX_L + r, BOX_R − r] 로 제한한다. 범위 밖으로의 입력은 누적되지 않아야 하며, 범위 끝에서 반대 방향 입력 시 즉시 움직여야 한다. | UR-001 | `drop()`, `keydown`, `aimX` |
| SR-006 | 드롭 후 550ms 동안은 추가 드롭을 받지 않으며, 그동안 조준 캐릭터를 반투명(불투명도 0.35)으로 표시한다. | UR-001 | `drop()`, `canDrop` |

### 4.3 합체 규칙

| ID | 소프트웨어 요구사항 | 상위 UR | 구현 위치 |
|---|---|---|---|
| SR-007 | 같은 단계의 두 캐릭터가 접촉하면 둘을 제거하고 두 중심의 중점에 다음 단계 캐릭터 1개를 생성한다. | UR-002 | `onCollide()`, `makeFace()` |
| SR-008 | 서로 다른 단계의 캐릭터는 접촉해도 합체하지 않는다. | UR-002 | `onCollide()` |
| SR-009 | 한 캐릭터는 한 번의 합체에만 참여한다. 같은 단계 3개가 동시에 접촉해도 합체는 1회만 일어난다. | UR-002 | `onCollide()`, `merged` |
| SR-010 | t 단계 두 캐릭터가 합체하면 (t+1)(t+2)/2 점을 더한다. | UR-003 | `onCollide()` |
| SR-011 | 최고 단계(9) 두 개가 합체하면 둘 다 사라지고, 합체 점수에 더해 200점 보너스를 주며 "세이렌 보너스 +200" 문구를 표시한다. | UR-002, UR-003, UR-008 | `onCollide()` |

### 4.4 점수·기록

| ID | 소프트웨어 요구사항 | 상위 UR | 구현 위치 |
|---|---|---|---|
| SR-012 | 화면 상단에 현재 점수, 최고 기록(= max(저장된 최고 기록, 현재 점수)), 다음 캐릭터 미리보기를 표시한다. 드롭하면 미리보기 캐릭터가 현재 캐릭터가 되고 새 미리보기가 선택된다. | UR-003, UR-004 | `frame()`, `drop()` |
| SR-013 | 최고 기록은 localStorage 키 `chiikawa-merge-best` 에 게임 오버 시 (더 높을 때만) 저장하고 시작 시 불러온다. 저장소를 쓸 수 없는 환경에서도 게임은 정상 동작한다 (기록은 0부터 시작). | UR-003 | `endGame()`, `chiikawa-merge-best` |

### 4.5 게임 오버·재시작

| ID | 소프트웨어 요구사항 | 상위 UR | 구현 위치 |
|---|---|---|---|
| SR-014 | 생성 후 1.2초가 지났고 속도가 1.5 미만인 캐릭터의 윗면이 위험선(y=148)보다 위에 있으면 위험 상태로 본다. 위험 상태가 누적 2.2초를 넘으면 게임 오버로 한다. 위험이 해소되면 누적 시간은 경과 시간의 2배 속도로 줄어든다. | UR-005 | `frame()`, `dangerTimer`, `DANGER_Y` |
| SR-015 | 게임 오버 시 물리 진행과 드롭을 멈추고 조준 캐릭터를 숨기며, 점수와 최고 기록을 담은 결과 화면을 표시한다. | UR-005 | `endGame()` |
| SR-016 | 결과 화면의 "다시 하기"를 누르면 캐릭터·점수·위험 시간을 초기화하고 컨테이너를 다시 만든 뒤 결과 화면을 닫는다. | UR-005 | `retry`, `init()` |

### 4.6 화면·플랫폼

| ID | 소프트웨어 요구사항 | 상위 UR | 구현 위치 |
|---|---|---|---|
| SR-017 | 게임 화면은 논리 해상도 440×720 을 유지한 채 창 크기(사방 여백 16px)에 맞춰 비율을 유지하며 확대/축소하고, 창 크기 변경 시 다시 계산한다. 캔버스 픽셀 수는 DPR 을 곱해 선명하게 그린다. | UR-006 | `resize()` |
| SR-018 | 게임은 단일 HTML 파일로 동작한다. 물리 엔진(matter-js 0.19.0)과 캐릭터 이미지 10종을 파일에 내장하고, 외부 참조는 Google Fonts 뿐이며 이를 받지 못해도(오프라인) 대체 폰트로 정상 실행된다. | UR-007 | `Matter`, `IMGS` |
| SR-019 | 합체 시 파티클 14개와 퍼지는 링 이펙트를 표시하고 새 캐릭터는 팝 애니메이션으로 나타난다. 이미지가 아직 로드되지 않은 경우 단계별 색상 원으로 대신 그린다. | UR-008 | `burst()`, `drawFace()` |
| SR-020 | 컨테이너 아래에 진화 단계 10종을 순서대로 화살표(›)로 이어 표시한다. | UR-004 | `frame()` |
| SR-021 | 위험선을 점선으로 표시하고, 위험 상태가 누적되는 동안 붉은색으로 깜빡여 강조한다. | UR-005, UR-008 | `frame()`, `dangerTimer` |
| SR-022 | 게임 루프는 requestAnimationFrame 으로 매 프레임 물리 갱신과 렌더링을 하며, 한 프레임의 물리 시간 간격은 최대 33ms 로 제한한다 (탭 전환 후 복귀 시 급격한 진행 방지). | UR-006 | `frame()` |
| SR-023 | 모바일에서 핀치 확대, 페이지 스크롤, 텍스트 선택을 막는다. | UR-006 | `user-scalable=no`, `touch-action` |

## 5. 제약 사항 및 가정

- 지원 환경: Canvas 2D, Pointer Events, ES2020 을 지원하는 최신 브라우저 (Chrome, Safari, Edge, Firefox).
- 물리 시뮬레이션 결과(쌓이는 모양)는 프레임 간격에 따라 달라질 수 있으며, 요구사항은 결정적으로 검증 가능한 규칙만 다룬다.
- 캐릭터 이미지는 팬 제작물 용도로 내장되어 있으며 저작권은 원저작자에게 있다.
- 이 사양서는 기존 구현(커밋 `0615c3d`)에서 역추출했다. 당시 구현과 달랐던 항목(SR-005 의 입력 누적 금지)은 v1.1 에서 구현을 수정해 반영했다.
